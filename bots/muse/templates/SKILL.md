# OpenLLM

## Purpose

Call the user's openllm.sh gateway (OpenAI-compatible API) to run chat
completions on any configured model or fallback chain, list available
models/chains, and check usage. Muse orchestrates: it picks the model or
chain, enforces spend discipline, and combines results with other tools.

## Tooling

CLI: `bin/openllm_cli.py` (stdlib only).

- `chat --model <id-or-chain> --message <text> [--system <text>]
  [--max-tokens N] [--temperature T]`
  → `POST {base_url}/chat/completions`. Prints assistant text + JSON footer
  (model served, tokens, latency).
- `models` → `GET {base_url}/models`. Prints available ids.
- `--base-url` overrides; otherwise `OPENLLM_BASE_URL`.

## Operating Rules

1. Check spend state before large or batched jobs; ask first if the scoped key
   is near its cap.
2. Prefer the user's named fallback chains over single models when they exist.
3. Always report which hop served the request — never present a
   fallback-served answer as the requested model's.
4. Never log, print, or persist the key, prompts, or completions. Metadata
   only (model, tokens, latency, cost).
5. If a model id is rejected, run `models` and show what's available instead
   of guessing.
